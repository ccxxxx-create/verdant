## 2. 目标与分级依据

**目标**：产出商业级品质、可长期运营内容的自研 2D 塔防游戏（类植物大战僵尸，原创"生物守家园 vs 怪兽入侵"题材）的完整设计文档与分阶段开发计划。本任务只交付文档，不动工写游戏代码。

**分级**：复杂任务（影响范围跨系统=引擎/架构/内容/双端；不确定性=需大量设计；不可逆性=技术选型沉没成本高）。

**已定稿决策**（阶段一/二闭环）：

| 决策项 | 结论 |
|---|---|
| 技术栈 | Phaser 3.90 + TypeScript + Vite；GitHub Pages 分发（同学平板开 URL 即玩） |
| 商业模式 | 品质对标商业级，暂不变现；单机、无账号、无 IAP、无后端 |
| 实施模式 | 全程由 AI 实施，用户审阅拍板 |
| 美术管线 | 程序化 SVG 矢量精灵 + 部件组合动画 + Phaser 3.60+ 粒子为主；AI 生图仅用于宣传主视觉 |
| 玩法骨架 | 经典多路车道格子 + 资源经济 + 波次进攻 |
| 难度定位 | 中度策略 + 挑战关（主线 6-10 小时轻松通关） |
| 美术风格 | 现代扁平矢量 + 光效 |
| 世界观 | 朴素框架：守护方=各世界原产生物，敌方=怪兽；命名随世界走，不做宏大叙事包装 |
| 首发世界 ×4 | 晨雾草原 → 珊瑚深海 → 天空浮岛 → 冰原霜境（沼泽毒瘴、地心熔岩列储备） |
| 创新机制（首批仅 1 项） | 地形连锁反应：积水导电 / 火蔓延 / 冰面滑行 |
| 关卡编辑器 | M4 后做，schema 与运行时同源 |
| 架构（三次采样收敛） | 场景：Boot(烘焙SVG)→Menu，GameScene ∥ HudScene；实体=Phaser.Container+可插拔行为组件（弃继承树、弃全量ECS）；动画=部件组合+Tween+粒子（弃Spine）；通信=全局EventBus+存档Store+局内隔离；数据=TS常量存原型/波次+JSON存关卡，Zod启动校验+version/migrate；关卡=模板+参数覆写生成 |

## 5. 留痕裁决表

| # | 裁决 | 理由 | 错了损失什么 |
|---|---|---|---|
| D1 | 引擎 Phaser 3+TS+Vite（Godot 落选：导出安卓/网页有音频内存坑，同学玩要装包；Cocos 生态小） | 用户约束：全程 AI 实施+同学平板直接玩+GitHub 载体+前端设计要求高 | 早期返工引擎迁移（约 1-2 周设计返工） |
| D2 | 美术=程序化 SVG 矢量+部件动画+粒子；AI 生图仅用于宣传 | 用户反馈 AI 生图不稳定；SVG 帧间一致、平板高分屏无损、AI 可全量产出 | 若最终想要手绘质感，需在第 M1 前后切换管线 |
| D3 | 玩法=经典多路格子+波次（弃自由路径/混合） | 用户选定；同学上手零门槛 | 差异化弱一点，靠地形连锁补 |
| D4 | 世界观=朴素生物vs怪兽（弃灵能-蚀能花哨框架） | 用户否决"太花哨" | 无 |
| D5 | 首发 4 世界并列设计，储备 2 世界只列名 | 用户全选 4 个 | GDD 篇幅变大，但一步到位 |
| D6 | 创新机制仅保留地形连锁（弃融合/进化/昼夜/拖拽法术） | 用户："不用太创新，朴素点" | 差异化单薄，靠内容量与品质补 |
| D7 | 编辑器 M4 后做，schema M0 即定 | 用户选定（三次采样分歧点裁决） | 前期手工造关卡略慢 |
| D8 | 数据=TS 原型常量+JSON 关卡+Zod+migrate | 三次采样 2/3 多数收敛 | 无实质风险 |
| D9 | 本任务不建 git 仓库、不上 GitHub（纯文档产物）；M0 开工时建 public 仓库 | 用户"先放到 GitHub 上面"指代码；public 是同学免登录访问 Pages 的必要条件 | 文档期无版本历史（可接受） |
| D10 | GitHub 仓库 Public（同学直接访问 Pages） | 用户明示给同学玩 | 代码公开（用户已接受） |

## 6. 验收标准（任务级）

1. GDD 覆盖：核心循环、4 世界设定、单位/敌人原型表（每世界 ≥6+≥8 且全数值）、地形连锁规则、关卡波次生成公式、进度/存档 schema、UI/UX 设计系统 token
2. DEV-PLAN 覆盖：架构（=三次采样收敛结论）、数据 schema、目录骨架、M0-M6 里程碑（每项可验收）、性能预算数值化、测试策略、Pages CI 要点
3. 工程质量：无 TODO 占位符；章节编号连续；交叉引用文件内有效；命名体系统一（朴素框架）
4. 流程质量：收尾审查 P0=0（独立子代理）；用户批准计划后方开工

## 7. 风险与对策（事前验尸）

**假如本项目已失败，最可能的原因**（逐条给对策+量化切换判据）：

| # | 失败原因 | 对策 | 量化切换判据 |
|---|---|---|---|
| R1 | SVG 部件动画外观不达标/管线不稳 | M1 先立"角色外观垂直切片"验收门槛（静止/待机/攻击/死亡 4 态），不过关不进 M2 | 连续 2 个工作会话外观不达验收即切换管线：预渲染帧动画+AI 静态图补关键帧 |
| R2 | 数值失衡：中后期过难或无聊 | 波次导演公式化；无头模拟（Node 跑逻辑）统计 50 次随机对局胜率方差 | 同一关卡胜率方差 >35% 即重调该世界数值 |
| R3 | 内容产能瓶颈（数百关手工写不动） | 模板+参数覆写生成；Zod 校验防呆 | 手工新增一关 >30 分钟即把编辑器从 M4 提前 |
| R4 | 平板性能不达标 | 性能预算硬编码（实体 ≤80、活粒子 ≤2000、纹理 ≤40MB、双端 ≥60fps）；特效分级（高/中/低自动降档） | 中端平板 <50fps 且降两档无改善即砍当世界特效层级 |
| R5 | 范围蔓延：世界/单位越加越多 | 首发版冻结=GDD 内容；新想法一律进 `docs/BACKLOG.md` | 任一 M 延期 >1 个工作会话即冻结并砍当期待办 |
| R6 | 无限拖延："慢慢来"变成不动 | 每个 M 都有可玩产出并推 GitHub Pages，让同学随时能玩形成外部反馈 | 同一 M 停滞 >2 周即降级范围保交付（可玩 > 完整） |
