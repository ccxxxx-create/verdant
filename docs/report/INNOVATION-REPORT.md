## 0. 勘察结论：文档说了什么 vs 代码实际有什么

先给一个决定所有建议权重的判断依据 —— **文档里写得最漂亮的部分，恰恰是代码里最空的部分**。

| 项 | 文档口径 | 代码实况 | 对创新的含义 |
|---|---|---|---|
| 战斗内核路径 | `src/core/sim` | 实为 `src/core/battle/`（`sim` / `director` / `traits` / `power` / `layout` / `types`） | 引用路径以代码为准 |
| **地形连锁** | GDD §7.1–§7.4（CellState / 导电 BFS / 火冰 / 风向暖流） | **完全未落地**。`level.ts` 有 `terrain` 四字段但 `sim` 从不读取；`CellState` 枚举不存在；`codex/terrain.ts` 是纯展示文案 | GDD 整章是「设计好未建的地基」，也是四世界差异化的唯一支点 |
| 波次导演 | GDD §8.2 含「不连续 3 波同敌」「同波 ≤2 种」 | `planWave` 有预算公式 + 大波灌场 + 前 3 波保底 + 同波 ≤2 + 提前收波；「不连续 3 波同敌」注释自认「留 W7 量产时终校」 | 导演系统是「半成品公式」，契约已稳定、扩展空间大 |
| 元层大招 / 传送带 | GDD §13.1/§13.2 | **已落地**（`power.ts`、`updateConveyor`） | 这一层反而超前于文档 |
| **动画五件套** | GDD §15 全套 + `PartAnimator` | **`PartAnimator` 不存在**。单位是一整张贴图 + ad-hoc tween；`CodexScene` 自称「过渡实现」 | GDD §15 是「写好了没做的规格」，补齐即创新 |
| 粒子 / 后处理 | GDD §11.4 特效预算表 | Phaser 3.60+ 粒子 API **一次未用**；碎屑是 `add.rectangle` | 整层空白 |
| 关卡编辑器 | DEV-PLAN §1.1 / §5（M4） | `EditorScene` 不存在 | 待建 |
| 无头 sim 扫荡 | DEV-PLAN §4「每关 50 局托管，方差 >35% 重调」 | `scripts/sim-sweep.mjs` + `npm run sweep` **已可用**，但只 `console.log` 文本、默认 skip、不进 CI、无结构化输出 | 仪表盘化是低风险高回报改造 |
| 图鉴击杀统计 | GDD §14.4「击杀统计依赖 M2 局内埋点，图鉴中先置灰标注」 | **未做**。`BattleStats` 只有 `kills/peakUnits/dug/mowersUsed/elapsedMs` | 文档自己预留了位置，纯增量 |
| 内容量 | 冻结 131 关 | **仅 6 个关卡 JSON**；巡野图已画 32 节点，26 关显示「量产中」 | **内容量是当前留存第一瓶颈 → 工具链创新 ROI 最高** |

### 三条不可碰的红线（贯穿下文所有方案）

1. **`UnitArchetype` / `EnemyArchetype` 是 `z.strictObject`** —— 加字段会破坏既有测试。新机制优先走 `traits: string[]`（零 schema 变更）或「可选字段 + 只增不删」。
2. **`BattleConfig` / 内核类型是普通 interface** —— 加可选字段不破测。已立下的纪律是「不新增 sim 命令、不改 EventBus 事件契约」。
3. **性能预算硬指标**（DEV-PLAN §3）：实体 ≤80、粒子 ≤2000、Tween ≤300、双端 ≥60fps，违反即返工。

## 1. 玩法机制创新

### 1.1 格状态机落地：把「地形连锁」从文案变成棋盘

- **一句话**：实现 GDD §7.1 的 `CellState` 状态机，并给玩家一个能「读出棋盘」的格状态可视化层。
- **玩家体验价值**：现在四个世界的高级机制全在图鉴文字里。落地后深海/冰原从「换配色 + 换数值」变成「换一个会反击的棋盘」——冰面的「滑」、水格的「电」成为可预判、可利用、也会误伤自己的资源。情绪上把「背板」升级为「做局」。
- **实现思路**：
  - 新建 `src/core/battle/terrain.ts`（纯函数，与 `traits.ts` 同规格、零 Phaser 依赖）：`CellState` 枚举 + `settle(cell, event)` 状态裁决（新覆盖旧；电气化只能从 Water 进入）+ 导电 BFS（GDD 已写好伪代码，可直接转测试）。
  - `sim.ts` 的 `step()` 增一次 `updateTerrain(state, dtMs)`；`AttackKind` 已有 `element`，命中回调直接喂给 terrain。
  - 渲染：`BattleScene` 加一层 `graphics` 覆盖（复用已有 cellHighlight 模式），水=淡青、电=锯齿描边、火=呼吸橙。
  - 内核契约：只往 `BattleState` 加可选 `terrain`，不新增命令、不改事件。
  - 工作量：**中**。
- **风险与回退**：每帧全格查询有成本 → 回退为「只在命中点局部 settle，不做全场扫描」。火焰蔓延有随机性 → **必须走 `state.rng`**（保 sim 可复现），不得用 `Math.random`。
- **衔接点**：GDD §7.1/§7.2/§7.3；BACKLOG「拖拽地形法术」的触发条件正是「编辑器稳定运行 1 个月后有扩玩法需求」——地形状态机是它的前置。

### 1.2 导演反制：让波次导演「看得见你的牌组」

- **一句话**：给 `planWave` 增加一层基于玩家当前 `state.units` 构成的反制权重，实现真正的动态难度。
- **玩家体验价值**：现在难度只有 `BASE × (1+w×GROWTH) × TEMPLATE_M` 一条刚性曲线，老玩家的最优解会被永远复用。反制层让「套路」有保质期——连赢三关后系统读出你的电系布阵并提高水行/铁甲权重。情绪价值是「被理解了」而不是「被惩罚了」。
- **实现思路**：`planWave` 选怪处插入权重表，读 `state.units` 的 `element` / `kind` 分布，对 `traits` 做 ±30% 加权（例：直射系 ≥4 → `shell_block_front` 权重 +30%，举壳兵本就是设计来克直射的）。全部权重落 `balance.ts` 新增 `DIRECTOR_COUNTER`。**零契约变更**。工作量：**小~中**。
- **风险与回退**：反制会被读作「作弊」→ **必须配合 1.5 的预告条显式提示**。幅度超过 ±40% 会让方差 >35%（DEV-PLAN §4 判据）。回退 = 只对 `element` 反制，不对 `kind`。
- **衔接点**：GDD §8.2；BACKLOG「敌人波次进化」的低成本前置版。

### 1.3 Boss 二阶段：用 traits 表达，不动 schema

- **一句话**：Boss 血量阈值触发第二阶段（换行为组 / 换速度 / 全场机制变化），全部用 `traits` 字符串声明。
- **玩家体验价值**：现在四个 Boss 都只是「血多的怪 + 一个定时器」。二阶段把 Boss 战从「计时沙漏」变成「有转折的对局」，是 Boss 关成为「每世界末关高潮」的必要条件。
- **实现思路**：`EnemyArchetype.traits` 已有，直接用 `boss_p2_hp60`、`boss_p2_enrage_frost` 等字符串（**零 schema 变更，规避红线 1**）。阈值检测放 `damageEnemy` 附近；`EnemyInst` 加可选 `phase` / `speedMul`（普通 interface，符合红线 2）。二阶行为复用 `traits.ts` 的纯函数模式。工作量：**中**。
- **风险与回退**：`speed` 冻结在 `def` 上，二阶段改速度需运行时倍率字段而非改 def。回退 = 只做「视觉 + 召唤频率」变化。
- **衔接点**：GDD §4.1–§4.4 四 Boss 既有弱点描述 —— 二阶段天然是「弱点轮换」：一阶段免疫当前被克制的属性，二阶段暴露。

### 1.4 规则卡化：把四世界差异做成「可装配的 RuleCard」

- **一句话**：把水格/断格/风向/寒潮实现为四张可组合的规则卡，每张卡是一组纯函数，同一 `step()` 内按关卡配置装配。
- **玩家体验价值**：真正实现「换世界 = 换玩法」——同时这是打开 BACKLOG「跨世界混合关」的唯一低成本路径，因为混合关 = 装配两张卡而不写任何新系统。
- **实现思路**：`src/core/battle/rules/` 每卡一个文件，导出 `{ id, apply(state, dt), terrain, uiHint }`；`LevelDef.terrain` 四字段即卡的选择器。装配逻辑在 `createBattle` 完成，`step` 只读列表。工作量：**大**（1.1 的架构化延伸）。
- **风险与回退**：卡间交互组合爆炸 → 用 `terrain.ts` 的状态裁决表收口成单一入口，禁止卡间互写。回退 = 每关只允许一张卡。
- **衔接点**：GDD §7.4；BACKLOG「跨世界混合关」。

### 1.5 波次情报预告条（低成本高感知）

- **一句话**：波间 18 秒间隙里，顶栏显示下一波的阵容预览（敌种头像 + 铁甲/飞行/成群标签）。
- **玩家体验价值**：把「随机袭击」变成「可读的牌」，这是类 PvZ 玩家呼声最高的信息层。同时它是 1.2 动态难度的**必要配套**（不透明动态难度 = 作弊感）。情绪上把试错成本从「输一关」降到「看一行字」。
- **实现思路**：`director.ts` 导出 `previewNextWave(state)`（纯派生，读 `spawnQueue` 计划结果——`planWave` 已是纯函数可直接预演）。`BattleState` 加只读缓存 `nextPreview`。HUD 在波间刷新，复用已有波次进度条 graphics。**零契约变更**。工作量：**小**。
- **风险与回退**：剧透降低难度 → 只显示「已亮相池中的敌种」（GDD §8.2 本限定「仅从本关已亮相池中加权随机」），不显示数量；或仅大旗波前显示（现已有 `warnHugeWave`）。回退 = 只显示敌种计数。
- **衔接点**：GDD §8.2「每个敌人须先在早 3 波内亮相过至少 1 只」——这条规则本身就是情报机制；`balance.ts` 的 `warningS`。

## 2. 元层 / 长线系统

### 2.1 道具合成 / 分解：给背包加「代谢」

- **一句话**：3 个同品质道具 → 1 个高一级品质（或反向分解为金币），让抽卡溢出的道具有出口。
- **玩家体验价值**：现在 4 个道具 + 单局只能带 1 个，重复抽取纯负反馈（普通道具权重 60%，最容易溢出）。合成把「重复」变成「进度」，是抽卡系统免于腻掉的最低配置。
- **实现思路**：配方表外置 `data/synth.ts`（`3 lightdew_jar → 1 energy_core`），避免污染 `ITEMS` 与 `ITEM_ACQUISITION` 的一一对应（已有测试守护）。`InventoryScene` 加「合成」页签（该场景已有页签结构）。**不新增存档字段**。工作量：**小**。
- **风险与回退**：无限刷 → 合成加金币手续费，且只向上不合重复同 id。回退 = 只做「分解为金币」。
- **衔接点**：`docs/PLAN-INVENTORY-GACHA.md` §3 道具表、§10 后续挂账。

### 2.2 本地赛季 + 每日种子关：无后端也能做的长线

- **一句话**：用「日期派生 seed + 关卡 id」生成每日固定挑战关，配合 4 周一轮的本地免费赛季轨。
- **玩家体验价值**：解决「打穿就没了」。每日关给一个「今天回来一次」的理由，且完全不需要 BACKLOG 里「每日挑战」要求的「有 10+ 人主动索取」这个触发条件。
- **实现思路**：seed = `hash(dateISO + levelId)`；`createBattle({ seed })` **已支持**——零内核改动。关卡数据仍取既有 JSON，只覆盖 seed 与 `starCondition`。赛季：`data/season.ts` + 存档加 `season` 字段（**需 v7 迁移**）。工作量：**小~中**（迁移 + UI 是大头）。
- **风险与回退**：本地时间可改 → 接受（GDD §1 已冻结无账号）。回退 = 只做每日关不做赛季轨。
- **衔接点**：BACKLOG「每日挑战（固定种子的条件关）」；GDD §2.5 局外循环；`rng.ts` 确定性随机。

### 2.3 图鉴击杀埋点与「初遇收集」（GDD 自己预留的位置）

- **一句话**：把 `enemyDeath` 事件按敌种落进存档，图鉴从置灰变成「已遭遇 X/44 · 已击杀 X/44 · 首次击败于 meadow-2-3」。
- **玩家体验价值**：收集驱动的核心钩子。「我打过的每一种怪」是图鉴的灵魂，而当前玩家对这 44 个敌人毫无个人记录。情绪上是「这是我的猎手笔记」。
- **实现思路**：`sim.ts` 已有 `{ t:'enemyDeath', enemy }`，`enemy.def.id` 现成；结算时落 `stats.killsByEnemy` 与 `stats.firstSeen`。存档 **v7**：`SaveV6` 被测试按名 import，**必须同步更新 `tests/save.test.ts` / `review-fixes.test.ts`**。`CodexScene` 条目改为真实进度条。工作量：**小**。
- **风险与回退**：存档膨胀 → 只存两个 Record 的键（≤44）。回退 = 只存总数。
- **衔接点**：GDD §14.4 原文预留；§14.1–§14.3 图鉴结构。

### 2.4 影子协作：无后端的「友军」

- **一句话**：玩家把一局通关的「卡组 + 道具 + 种子 + 成绩」编码成一段短码分享，朋友导入后在同一 seed 上复现并回传结果码。
- **玩家体验价值**：GDD §1/§9.2 冻结「无账号无后端」，传统联盟协作做不了。但「输给他/她」这件事不需要服务器——只需要一段可校验的码。情绪价值是「有人在跟我打同一局」。
- **实现思路**：`deck[8] + carriedItem + seed + levelId + result` → base32 短码（id 已有稳定字典序，可查表压缩）。结算页加「生成挑战码」；主界面加「迎战」输入框（**复用 `ui/redeem.ts` 已建好的屏幕键盘 + 物理键盘 + 防重入结构**）。工作量：**中**。
- **风险与回退**：码长不可用 → 只做单向分享；或只分享 seed 不分享 deck。回退成本低。
- **衔接点**：BACKLOG「云存档」；`ui/redeem.ts` 输入范式；`core/gacha.ts` 的确定性 `Rng`。

### 2.5 成就墙：把两个孤零零的常量变成一个系统

- **一句话**：`data/achievements.ts` + 成就墙场景，把 `STAR_MILESTONES`、`BOSS_FIRST_KILL_REWARD` 扩成 ~30 条可追踪成就。
- **玩家体验价值**：给「全收集」一个比星星更细的刻度。星星只有「通关/无破损/限定条件」三轴，成就能刻画「用炸弹菇单杀 10 只铁甲」「零伤害通关」这类玩家自认的高光时刻。
- **实现思路**：条件走「事件派生」——`BattleEvent` 联合已有 `enemyDeath/unitDeath/mower/blast` 等足够信号；结算时汇总一次判定，**不进 sim**。工作量：**小~中**。
- **风险与回退**：需要 v7 存档字段；回退 = 只做展示型成就（无奖励），零存档变更。
- **衔接点**：GDD §2.5；`data/economy.ts` 的 `STAR_MILESTONES`、`BOSS_FIRST_KILL_REWARD`（后者已定义但未接入，注释自认「M3 Boss 关接入」）。

## 3. 表现层创新

> 纪律提醒：全仓**禁止栅格图片**，一切走 `palette.ts` 字符矩阵 + `bakePixelTexture` 图形绘制。以下每条都只动矩阵 / 图形 / tween / camera。

### 3.1 分件 + PartAnimator：GDD §15 从规格变成代码

- **一句话**：把单位从一张 32×32 贴图拆成 2~3 个部件容器，落地 `fx/PartAnimator.ts` + `data/clips/*.ts`，实现五件套。
- **玩家体验价值**：GDD §15.1 自己定的目标是「PvZ2 级活物感——不是会动的贴图」。当前单位正是「会动的贴图」（单 image + 一行 `setAngle` 摇摆）。**这是当前与外显品质差距最大的一处**。
- **实现思路**：`scripts/gen-pixel-units.mjs` 扩展为按 y 区间切层（GDD §11.2 已写切分规则：脸 y15-18 / 身体 y13-28 / 顶部职能特征件），输出 `unit_<id>_part_<n>`。`fx/PartAnimator.ts` 只做属性插值，Tween 计入 ≤300 预算；clip 数据落 `data/clips/`，缺省用角色模板 clip。**完全不碰内核**。工作量：**中~大**。
- **风险与回退**：①切件会破坏 `tests/pixels.test.ts` 的矩形网格校验 → 每部件单独校验；②多 Sprite 提高 draw call → 需 benchmark 双端 60fps；③**回退路径清晰**：保持整图，PartAnimator 只驱动整体 `scale/rot/alpha`（工作量降到「小」，仍让全部 13+ 单位获得预备-发射-收招三段式手感）。
- **衔接点**：GDD §15.1–§15.3（含 M1 落地顺序与「减弱动态」开关）；DEV-PLAN §1.4；`archive/PLAN-M1B.md` 的 C7 欠账；`kit.breathe()` 已有门控范式。

### 3.2 时域光照：晨 / 午 / 暮三套背景变体（不动昼夜玩法）

- **一句话**：同一确定性种子 + 不同色映射，`bg/meadow.ts` 生成晨/午/暮三张背景，随关卡进度或真实时段淡切。
- **玩家体验价值**：GDD §4.1 主题是「晨雾草原」、§3.1 基调是「薄雾笼罩」，但目前只有一张正午亮背景。三段光照让「长夏」有时间的流动感。
- **实现思路**：`meadowBattleBg()` 已参数化为确定性生成 → 追加 `variant: 'dawn'|'noon'|'dusk'`，在 `set()` 后过一张色映射表。**关键约束**：「暮色」若走变暗会撞 `tests/pixels.test.ts` 的亮度底线测试（`palette.ts` 明写「亮度底线有测试守护，防回退到暗色」）→ **解法：夜 = 蓝移/暖移而非压亮度**，保持高亮度、只改色相。工作量：**小~中**。
- **风险与回退**：亮度测试需为 dusk 变体单独放行或保持高明度；平板性能无影响。回退 = 只换天空带三色。
- **衔接点**：BACKLOG「昼夜双场」（本项**明确不做玩法切换**，只做表现层，故不受 GDD §7 冻结约束）；GDD §11.0 背景生成器；§12.2 世界音乐。

### 3.3 粒子地形交互：让地形有表情

- **一句话**：启用完全未使用的 Phaser 粒子 API，并让粒子成为地形状态的信使（冰面留晶、水格溅电、火蔓冒烟）。
- **玩家体验价值**：地形连锁如果只有格子变色，玩家依然读不出「刚刚发生了什么」。粒子把不可见的 BFS 传导、随机蔓延概率变成可见的因果链——这是让复杂机制「看起来很简单」的关键。
- **实现思路**：新建 `fx/ParticleFactory.ts` + 对象池；粒子纹理从 `PALETTE` 现取色生成 2×2/4×4 像素纹理（走 `bakePixelTexture`，合规）。事件源 `BattleEvent` 已含 `hit/blast/stun/web/shieldBreak/mower`。按 `settings.quality` 三档缩放（已有 auto/high/medium/low）。工作量：**中**。
- **风险与回退**：粒子是帧率第一杀手 → `npm run sweep` 增加粒子计数断言，中低档关闭地形粒子。回退 = 全部退回 `add.rectangle` 碎屑。
- **衔接点**：GDD §11.4 特效预算表；DEV-PLAN §3 与画质三档。

### 3.4 镜头语言：hit-stop 是最便宜的大招

- **一句话**：`step(state, dtMs)` 的 dtMs 由场景传入 → 关键时刻把 dt 缩放 ×0.15 持续 120ms，即得慢镜；再加行聚焦与 Boss 镜头推移。
- **玩家体验价值**：一击必杀的满足感 80% 来自那 100ms 的凝固。Boss 破阶段、大旗波、最后一个敌人倒下——这三处慢镜能让全关的记忆点从「我赢了」变成「那一秒」。
- **实现思路**：`sim.ts` 的 `step(state, dtMs)` 签名已接受 dtMs，`BattleScene.update()` 传 `dt * speed * slowFactor` 即可。**零内核改动、零契约变更**。RNG 仍走 `state.rng`，只是时间流速变慢 → **sim 复现性不受影响**（同 seed 同操作序列仍得同结果，只是墙钟时长不同）。镜头推移用 `cameras.main.pan/zoom`（已有 `shake`/`flash` 路径）。工作量：**小**（hit-stop）/ **中**（镜头推移）。
- **风险与回退**：GDD §10.2「对局内禁止超过 200ms 的阻塞动画」——慢镜**不阻塞输入**（sim 仍在跑），合规；但「初见特写」若做成定格则违规（见 4.3）。回退 = 慢镜只在 `waveWarning` 一处。
- **衔接点**：GDD §11.4；DEV-PLAN §3 Tween 预算；`BattleScene` camera 用法。

### 3.5 像素风后处理（高成本差异化，需实测）

- **一句话**：用 Phaser 3.90 的 PreFX/PostFX 加扫描线、暗角、极轻色差，强化「老屏幕显像管」质感。
- **玩家体验价值**：像素风最怕「高清屏上的模糊放大」。轻后处理能让 ×3/×5/×6 的整数放大仍有质感而非「马赛克照片」。
- **实现思路**：`preFX.addVignette()` 或 PostFX pipeline；按 `settings.quality` 三档开关。工作量：**中**。
- **风险与回退**：**性能风险最高的一条**——后处理是全屏 shader，≥60fps 与平板 1280×800 是硬验收，不达标即返工。必须先 benchmark 再进主干；低画质档必须完全关闭。回退 = 不做，改用在背景矩阵里直接画扫描线（零运行时成本）。
- **衔接点**：GDD §10.4 双端适配；DEV-PLAN §3；`settings.quality` 三档。**建议只作为 M6 打磨期的可选项，不列入 Top 5。**

> 附注：本次已落地的 **nearest-neighbour + roundPixels + antialias:false**（见 §6）属于同一目标下**零成本**的部分 —— 它已经解决了「模糊放大」的主要问题，后处理只是锦上添花。

## 4. 叙事与情感

### 4.1 指间之光：把 GDD §3.1 的设定做成交互

- **一句话**：玩家是「看火人」，只作为「指间的一束光」——种植时从光标流出一束光落地长成植株；收集光露时光标拖一道金痕。
- **玩家体验价值**：GDD §3.1 的三句话设定（薄雾大陆 / 裂隙 / 看火人）目前**零交互承载**——玩家在所有 UI 里只是个隐形手指。这一条让世界观第一次通过手部动作传达，而非通过文案。
- **实现思路**：`BattleScene` 的幽灵预览从「半透明贴图」升级为「光 → 实体」的 140ms 生长（GDD §11.4 已有「种植 scaleY 挤压回弹 140ms」）；光痕 = 一个短寿命 `graphics` 线。工作量：**小**，契约零。
- **风险与回退**：光痕泛滥影响可读性 → 只在种植成功时触发，收集只做缩放反馈。
- **衔接点**：GDD §3.1 / §10.3 / §11.4。

### 4.2 让 flavor 走出图鉴：长按即自我介绍

- **一句话**：单位与敌人的 `flavor`（schema 必填，≤60 字）长按 1.2s 在对局内弹出小卡。
- **玩家体验价值**：`flavor` 现在是只给图鉴看的字段。玩家在编成/对局中记不住 13 个单位谁是谁，而 flavor 正是为解决「这个单位是什么/怎么用」写的。让它在决策现场出现，角色才开始被记住。
- **实现思路**：种子卡与场上单位的 `pointerdown` 计时器；复用 `ui/components/overlay.ts` 的弹层。工作量：**小**。
- **风险与回退**：对局文字干扰 → 弹层半透明 + 长按才出，且受「减弱动态」门控。
- **衔接点**：GDD §14.2/§14.3；`unit.ts` 的 `flavor` 字段。

### 4.3 初见特写：新敌人的 400ms 定格（非阻塞）

- **一句话**：某敌种在本局首次登场时镜头轻推 + 名称卡 + 敌人放大 400ms，**不暂停 sim**。
- **玩家体验价值**：既是叙事（「雾里走来一个新东西」）也是教学（GDD §8.2「亮相池」机制的视觉化），与 1.5 的预告条互为表里。它把「怎么又出新怪」的挫败感转成「又认识一个」的好奇心。
- **实现思路**：`sim.ts` 已有 `enemySpawn` 事件；`BattleScene` 维护 `seenEnemyIds: Set<string>`，命中新 id 播一次 tween + 文字。工作量：**小~中**。
- **风险与回退**：**与 GDD §10.2「对局内禁止超过 200ms 的阻塞动画」存在口径冲突** → 严格做成非阻塞并行动画（sim 照跑，只加一层视觉）；若审查认为仍干扰节奏，退化为「名称角标 200ms 淡入」。**此项需拍板。**
- **衔接点**：GDD §8.2；`planWave` 的「前 3 波保底」；§10.2 动效约束。

## 5. 工程 / 工具链创新

### 5.1 关卡编辑器 + 边改边扫（DEV-PLAN M4 的增强版）

- **一句话**：`EditorScene` 复用 `LevelDef` schema 与渲染层，且**编辑器内嵌真实无头 sim**，改完一键跑 20 seeds 看胜率。
- **玩家体验价值**：不直接给玩家，但它是「26 关未量产」这个当前最大瓶颈的唯一解。DEV-PLAN 把编辑器定位为「深海 26 关」的配套——而草原还剩 26 关。
- **实现思路**：编辑器复用 `LevelDef` strict schema 做表单；预览直接 `createBattle` + `step` 循环（内核零 Phaser 依赖，这是仓库最有价值的架构红利）；导出 JSON 落 `src/data/levels/*.json`，`import.meta.glob` 自动收编。工作量：**大**。
- **风险与回退**：编辑器本身引入输入/序列化的新复杂度 → 先做「只读 JSON 校验 + 一键起局」的最小版，再逐步加编辑。回退 = 只做 JSON schema 校验器 + 命令行扫荡。
- **衔接点**：DEV-PLAN §1.1 / §5 M4；BACKLOG「拖拽地形法术」以编辑器稳定为前提。

### 5.2 扫荡仪表盘：把 `npm run sweep` 从日志变成报告

- **一句话**：sweep 输出结构化 JSON，`scripts/balance-report.mjs` 生成一张静态 HTML 平衡报告页。
- **玩家体验价值**：间接但决定性——DEV-PLAN §4 的判据「每关 50 局托管，胜率方差 >35% 重调」现在**无法执行**，因为 sweep 只打印文本且默认 skip。仪表盘把「数值拍脑袋」变成「看一眼报告」，直接服务 26 关量产与四世界配平。
- **实现思路**：`tests/sim-sweep.test.ts` 已有统计循环 → 加 `JSON.stringify` 落 `docs/_review/sweep.json`；新脚本生成 HTML（可参考既有 `scripts/gen-almanac.mjs` 的 Node 出静态页范式）。工作量：**小~中**。
- **风险与回退**：CI 耗时随 seeds × 关卡线性增长 → 阈值化：PR 跑 2 seeds，每日 cron 跑 50 seeds。回退 = 只输出 JSON 不出 HTML。
- **衔接点**：DEV-PLAN §4；`scripts/sim-sweep.mjs`；`scripts/gen-almanac.mjs`。

### 5.3 失败归因埋点：让 sim 说出「为什么输」

- **一句话**：`BattleStats` 增加 `loseReason`（敌种 + 行号）、`unitDeathsByEnemy`、`lightdewCurve`。
- **玩家体验价值**：现在扫荡只知道「输了」，不知道「被什么在哪行打穿」。这是 1.2 动态导演的反馈信号来源，也是人工调平的唯一依据。
- **实现思路**：`sim.ts` 的 `state.status='lost'` 处记 `e.def.id` 与 `e.row`；`BattleStats` 加可选字段。工作量：**小**。
- **风险与回退**：事件量大 → 只聚合计数，不存序列。
- **衔接点**：GDD §14.4 的埋点缺口；DEV-PLAN §4。

### 5.4 PCG 作为量产填充器（不是关卡设计者）

- **一句话**：用波次导演 + RuleCard 生成 26 关的**草稿 JSON**（pool + 地形 + 模板），人工只做教学节奏与三星条件的修正。
- **玩家体验价值**：直接打「26 关未量产」。关键设计判断：**PCG 不生成结构**——T-TEACH/T-NORMAL/T-FLAG/T-SURVIVE/T-BOSS/T-CONVEYOR/T-CHAL 七类模板由 GDD §8.1 冻结，PCG 只填参数。这样生成的关卡有手工模板的骨架，没有 PCG 常见的「_random 感」。
- **实现思路**：`scripts/gen-levels.mjs`，输入世界/段位索引，输出关卡 JSON；用 `registry.validateRegistry` 保证引用的敌种/单位 id 合法。工作量：**中**。
- **风险与回退**：生成关缺乏教学曲线 → **PCG 产物一律标记草稿，必须过 `tests/levels.test.ts` + 一次人工审读**；只允许用于 T-NORMAL 填充，T-TEACH/T-CHAL/T-BOSS 保持纯手工。回退 = 只生成 `pool` 与 terrain，waves/starCondition 手写。
- **衔接点**：GDD §8.1 / §8.3 / §8.4；`map/meadow.ts` 已画好的 32 节点。

### 5.5 CI 门禁化与漂移检测

- **一句话**：almanac 生成物与 archetypes 的漂移检测、像素规范化、sweep 小样本，全部进 CI。
- **实现思路**：`scripts/gen-almanac.mjs`（README 让人工跑）+ `normalize-pixels.mjs` + sweep 2 seeds 三步进 workflow。工作量：**小**。
- **衔接点**：GDD §8.2「改后运行 node scripts/gen-almanac.mjs」；DEV-PLAN §6 CI。
